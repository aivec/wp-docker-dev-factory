# v4.0.0 変更履歴（Changelog）

## 概要

これまで本ツールは、**visiblevc** が提供していたカスタム Docker イメージをベースにしていました。しかし、このイメージは PHP 8.0 以降メンテナンスが停止されており、新しい PHP バージョンへの対応が困難な状況となっていました。

そのため v4 では、**公式の WordPress Docker イメージ**へ移行しました。これにより最新の PHP バージョンをサポートできるようになりましたが、同時にコンテナの挙動やライフサイクル管理に関していくつか重要な変更が加わっています。これらのアーキテクチャ上の違いについては、本ドキュメントの後半で詳しく説明します。

---

## ✨ 新機能

- **PHP 8.2、8.3、8.4、8.5** のサポートを追加
- 新しいコマンド **`Stop & Remove Containers`** を追加
- `wp-instances.json` に新しい `wordpress` オブジェクトを追加

---

## 🔄 変更点

- **`Stop WordPress`** コマンドを **`Stop Containers`** に名称変更  
  - コンテナを削除せず、停止のみを行うように変更
- `wp-instances.json` のフィールド構成を変更:
  - `wordpressVersion` → `wordpress.version`
  - `locale` → `wordpress.locale`

---

## ❌ 削除された機能

- **`Save snapshot`** コマンドを削除  
  - 公式 WordPress イメージの挙動により、この機能は不要となりました
- **PHP 7.1、7.2、7.3** のサポートを終了
- **FTP / SSH 経由でのプラグイン・テーマダウンロード機能**を削除  
  - ストレージを Synology NAS から **AWS S3** に移行したため、継続してサポートする必要がなくなりました

## 🏗 アーキテクチャ上の変更点

### データベースの分離

これまでは、すべての WordPress インスタンスが単一の MySQL コンテナを共有していました。そのため、インスタンスごとに異なるデータベースサーバーバージョンを使用することができず、環境間の分離性にも制限がありました。

v4 では、**各インスタンスごとに専用の MySQL コンテナを起動**するように変更されています。これにより、以下の点が改善されました。

- インスタンス間の分離性向上
- 柔軟性の向上
- 環境間の再現性向上

### WordPress イメージの挙動

従来のバージョンでは、Docker イメージ内に WordPress が事前インストールされていなかったため、コンテナを削除・再起動するたびに WordPress 環境全体を再構築する必要がありました。

公式 WordPress Docker イメージでは WordPress があらかじめ含まれているため、以下のメリットがあります。

- 起動時間の大幅な短縮
- コンテナ再起動の簡素化
- ライフサイクルおよび永続化の挙動が明確化
