# v4.0.0 Changelog

## Overview

Prior to v4, this tool was built on a custom Docker image maintained by **visiblevc**. That image stopped receiving updates after PHP 8.0, which made continued support for newer PHP versions impossible.

As a result, v4 migrates to the **official WordPress Docker image**. While this unlocks support for modern PHP versions, it also introduces meaningful changes in container behavior and lifecycle management. These architectural differences are described in detail at the end of this document.

---

## ✨ New Features

- Added support for **PHP 8.2, 8.3, 8.4, and 8.5**
- Added a new command: **`Stop & Remove Containers`**
- Introduced a new `wordpress` object in `wp-instances.json`

---

## 🔄 Changes

- Renamed **`Stop WordPress`** to **`Stop Containers`**
  - This command now **stops containers without removing them**
- Moved `wp-instances.json` field:
  - `wordpressVersion` → `wordpress.version`
  - `locale` → `wordpress.locale`

---

## ❌ Removed Features

- Removed the **`Save snapshot`** command  
  - This is no longer necessary due to differences in how the official WordPress image manages state
- Dropped support for **PHP 7.1, 7.2, and 7.3**
- Removed support for **plugin/theme downloads via FTP and SSH**  
  - Since storage was migrated from the Synology NAS to **AWS S3**, this functionality is no longer needed

## 🏗 Architectural Changes

### Database Isolation

Previously, all WordPress instances shared a single MySQL container. This prevented instances from running against different database server versions and reduced isolation between environments.

In v4, **each instance now runs its own MySQL container**, providing:

- Improved isolation
- Greater flexibility
- Better parity between environments

### WordPress Image Behavior

In earlier versions, WordPress was **not pre-installed** in the Docker image. As a result, removing and restarting containers required rebuilding the entire WordPress environment each time.

The official WordPress Docker image includes WordPress by default, which:

- Significantly reduces startup time
- Simplifies container restarts
- Changes how lifecycle and persistence are handled
